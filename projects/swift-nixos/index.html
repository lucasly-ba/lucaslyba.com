Overview

NixOS doesn't fit the assumptions most build systems make about a Linux toolchain — and Swift's build is one of the trickiest. This project is a single flake.nix that builds the complete Swift 6.5 toolchain from source on NixOS, reproducibly, from a clean dev shell.

Getting there meant reverse-engineering the Swift build and solving a deep cascade of toolchain problems.

Problems solved

  • DT_RUNPATH vs transitive rpath — nixpkgs forces non-transitive DT_RUNPATH, but Swift assumes transitive DT_RPATH; built a complete bootstrap runtime so the just-built tools resolve libdispatch/Foundation at runtime.
  • glibc sysroot detection — Swift's ClangImporter looks for libc in an empty /usr/include on NixOS; pointed it at a constructed sysroot of glibc headers and libs.
  • Bootstrap compiler — wired up nixpkgs' prebuilt Swift as the bootstrap toolchain.
  • ncurses shimming — Swift links bare -lcurses, which nixpkgs doesn't ship; built a compat shim mapping it to libncursesw.

The full stack builds

It isn't just the compiler. From a clean dev shell, dobuild.sh exits 0 building the whole toolchain, and each layer is verified running:

  • Compiler + standard library (Swift 6.5-dev) — a clean single build exits 0.
  • C++ interop (CxxStdlib) — verified printing a std::string from Swift.
  • libdispatch and Foundation — import Foundation with Date / JSON / UUID / NSString all working.
  • Test suite — Parse 252/252 and Interpreter 257/260 pass, achieved with zero edits to the Swift or LLVM trees (flake-only).

The deepest bug — executable tests segfaulting in libc — was root-caused under gdb to a bare-clang baked dynamic linker mismatching the Nix glibc in the RUNPATH, then fixed entirely in the flake's shell hook. The full write-up is in the build journey.
