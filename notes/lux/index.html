Lux: building an editor by hand

Lux is a modal, Helix-inspired terminal editor in Rust. The whole point was to build the parts real editors rely on — the text structure, the syntax engine, the undo system, the LSP client — rather than import them, so the internals are understood instead of trusted.

The rope, not a string

The text buffer is a rope rather than a flat String. A string makes an insert in the middle of a large file an O(n) memmove; a rope keeps edits cheap by storing text as a balanced tree of chunks. Everything above it — cursors, selections, rendering — addresses text through the rope, so the editor stays responsive on big files.

Undo as a tree

Most editors model undo as a linear stack: redo is lost the moment you type after undoing. Lux models history as a tree, so branching edits are all reachable. It's a small data-structure decision that changes how editing feels — you never lose work by exploring an alternative.

Incremental syntax

Highlighting is driven by tree-sitter, re-parsed incrementally as you type — only the edited region is re-analyzed, not the whole file each keystroke. The tree-sitter grammars are C compiled at build time, which is the reason the Nix dev shell carries a full C toolchain alongside the Rust one.

A hand-written LSP client

Lux speaks the Language Server Protocol to rust-analyzer over a hand-rolled JSON-RPC client — request/response correlation, notifications, document sync — for live diagnostics and completion. Writing the client by hand (rather than pulling a crate) was the fastest way to actually learn how editors and language servers talk.

The audit — bugs the tests missed

92 tests cover the internals, but the most useful part of the journal is the honest section on what they didn't catch: the edge cases that only show up against a real terminal and a real language server. That gap — between "structurally correct and tested" and "proven against a live display" — is the part most write-ups skip, and the part worth reading.

The full developer log walks the codebase module by module — rope/, text/, history/, editor/, syntax/, lsp/ — in the order it was built. It's in JOURNEY.md.
